# Part 2 verification

This work starts from the imported published theme at commit `406dcea`. No Shopify theme was published or changed during this work. The isolated checkout has no package manifest, so there are no project lint or typecheck commands. `node --test tests/quick-add.test.mjs` passes 7 of 7 tests, `git diff --check` passes, and Theme Check reports 0 errors with 9 existing warnings across 155 files. Running the same node tests with `TEST_SOURCE_REF=406dcea` fails 7 of 7. That shows the fixes and the new safeguards are absent from the baseline; it does not mean every test represents a separate baseline regression.

The first issue sent the wrong variant to cart from quick add. In Safari, selecting Pair at 139 on the Assessment Single and Pair Options quick-add form put Single at 79 in the cart. This showed the wrong variant and cart price; no checkout or charge was performed. `assets/product-info.js` refreshed the product display but did not refresh the hidden product-form variant input, so it retained the first variant ID. The fix calls the existing `updateVariantInputs` method during each valid variant update. `snippets/buy-buttons.liquid` also renders the selected price beside Add to cart. The actual-method VM test calls `ProductInfo.handleUpdateProductInfo`: baseline source leaves the input as Single, while the changed source sets it to Pair. A second actual-method test verifies that the selected submit price changes from `$10.00` to `$8.00`. Browser QA still needs to confirm the rendered price and cart line in the unpublished draft.

The second issue allowed repeated add-to-cart submissions while the first request was pending. A normal visible double click produced one added item in the observed browser flow, but the controlled VM reproduction exposed two submits before the first request settled. This can create an unintended extra quantity when an event reaches the form twice. `aria-disabled` exposes state to assistive technology but does not reject JavaScript submit events. `assets/product-form.js` now tracks an in-flight request with `isSubmitting` and clears it in `finally` after both success and network failure. The actual submit-handler test starts two deferred requests before completion: baseline source starts two requests and the changed source starts one. It then resolves one request and rejects a later one, confirming the form clears `isSubmitting` and permits a retry. Browser QA still needs to confirm the visible loading and error state in the unpublished draft.

The third issue blocked mobile navigation from a collection-card image. In Safari Responsive at 393 by 852, tapping the Assessment Compare At Price image on `/collections/all` left the shopper on the collection page, while the title opened `/products/assessment-compare-at-price` correctly. Desktop image navigation passed. This prevents mobile shoppers from opening the product from its main visual and creates a conversion risk. In `assets/component-card.css`, the mobile rule at 749px and below gave `.card__heading a::after` a `z-index` of `-1`, placing the card-link overlay behind the card. The fix removes those six lines so the normal overlay remains active. The fixed browser retest is pending and no automated CSS pass is claimed. Live QA must check the image, title, neighboring card overlays, and wishlist or other card overlays on the unpublished draft.

The quick-add drawer adds safeguards beyond the three seeded defects. `assets/quick-add.js` now owns each load with an `AbortController`, ignores stale responses, and only resets the opener for its active request. It renders localized error text and a View product details link when loading fails. Four actual-method VM tests confirm that an older response cannot open over a newer product request, an older `finally` cannot clear the same opener's new loading state, a fetch error creates the localized alert and details link then resets the button, and closing aborts the request without reopening the modal. These tests use fake DOM objects to isolate lifecycle behavior. Browser QA still needs to confirm focus management, animation, and the visible error state in the unpublished draft.

The feature adds the global Theme settings Cart Quick add desktop and tablet choice. Popup remains the existing default. Drawer uses the right-side quick-add drawer from 750px upward, while mobile keeps the popup. The selected button price is shown only for the drawer.
